# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

AI contract review assistant for Vietnamese SMEs (product name **LawScan**, FPT capstone). Two independent npm projects, no root package: `backend/` (Express + TypeScript API and BullMQ workers) and `frontend/` (Next.js App Router). Run every command from inside the relevant folder. UI copy, routes (`/dang-nhap`, `/goi-dich-vu`, `/loi-moi`, …) and many docs are in Vietnamese.

## Commands

### Backend (`backend/`)
```sh
docker compose up -d          # mongo (replica set rs0), redis, mailpit — Redis is required to boot
npm run dev                   # API on :4000, Swagger at /api-docs; also runs workers when START_WORKERS=true
npm run dev:worker            # workers only (src/worker.ts), use with START_WORKERS=false on the API
npm run build                 # tsc -> dist/
npm run lint / lint:fix / format
npm test                      # pretest runs build, then jest --runInBand
npm run build && npx jest tests/payments.test.js   # one test file
npx jest tests/payments.test.js -t "name"          # one test case
```
Tests are plain JS/CJS in `tests/` and **require the compiled `dist/` output** (`require('../dist/...')`), so rebuild after changing `src/` before running a single test. They use `mongodb-memory-server` (replica set) and `supertest` against `createApp()`, set env vars at the top of each file, and mock external providers (payOS, Gemini, Brevo, Cloudinary).

### Frontend (`frontend/`)
```sh
npm run dev          # :3000; needs backend at API_BASE_URL (default http://localhost:4000)
npm run build
npm run lint
node --test scripts/*.test.mjs               # all logic tests
node --test scripts/review-timeline.test.mjs # one test file
```
Frontend tests use Node's built-in runner: they transpile a single `.ts/.tsx` file with the `typescript` API and run it in a `vm` context with hand-stubbed dependencies, so no Next/React runtime is involved. `frontend/docs/api-integration-status.md` lists lint + tests + build as the pre-merge check.

## Architecture

### Request path
Browser → Next.js route handlers in `frontend/app/api/**` → backend `/api/v1/**`. The browser never calls the backend directly. Auth tokens live in httpOnly cookies (`lawscan_access`, refresh cookie); each route handler reads the cookie and forwards `Authorization: Bearer`. Shared proxy helpers are in `frontend/lib/api/*-proxy.ts` (they also validate 24-hex ObjectIds). Client code calls `/api` through the axios `apiClient` (`lib/api/client.ts`), which normalizes errors to `ApiClientError` and does single-flight token refresh. Data fetching uses TanStack Query hooks in `hooks/` with keys in `lib/query-keys/`.

Backend responses are always `{ success: true, data, meta? }` (`utils/ApiResponse.ts`) or an error envelope from `errorHandler`; throw `AppError` (`AppError.badRequest/forbidden/...`) instead of writing responses. Layering: `routes` (with `validate({ params, query, body })` zod schemas from `validations/`) → `controllers` (wrapped in `asyncHandler`) → `services/<domain>/` → mongoose `models/`.

### Multi-tenancy and roles
Everything is scoped by organization (`orgId`); services filter by it (e.g. `ContractModel.findOne({ _id, orgId })`) and return 404 for other orgs. Roles: `administrator, owner, manager, staff, expert, user` — enforced by `requireRole` and the role lists in `middlewares/rbac.middleware.ts`, mirrored on the frontend in `config/dashboard-roles.ts` and the per-role route trees `app/(dashboard)/dashboard/<role>/`. `user` is a personal account; personal vs. business accounts may only review certain contract types (`services/contract/personalReviewPolicy.ts`).

### Background pipeline (BullMQ on Redis)
`services/workers.service.ts` starts three workers, created via helpers in `config/queue.ts` (`createQueue/createWorker/addJobWithTimeout`; enqueue fails with 503 after 5s if Redis is down):
1. **Extraction** (`contract/extractionWorker.service.ts`): on upload, extracts text from PDF/DOCX/DOC (pdf-parse, mupdf, mammoth, word-extractor, tesseract OCR) into a `ContractVersion`.
2. **Review** (`review/reviewWorker.service.ts`): a `Review` doc tracks stages `segmentation → summary → riskDetection`; waits for extraction, then runs `analysis/` services. Progress is published via QueueEvents and streamed to clients over SSE (`GET /reviews/:id/events`, `utils/sse.ts`); the frontend falls back to polling. Usage/credits are leased and finalized via `billing/usage.service.ts`.
3. **Legal ingestion** (`legal/legalIngestionWorker.service.ts`): parses admin-uploaded legal sources into `LegalKnowledgeChunk`s with Gemini embeddings.

Risk detection and chat are RAG over legal knowledge: `legal/legalRetrieval.service.ts` combines MongoDB Atlas `$vectorSearch` and `$search` (indexes created at boot by `ensureLegalVectorIndex/ensureLegalTextIndex`), so these need an Atlas-compatible MongoDB.

### AI and privacy
All LLM calls go through `services/ai/llm.service.ts` (Google Gemini via `@google/genai`: `generateJson`, `generateText`, `generateTextStream`, `embedTexts`). Contract text is redacted before being sent to the model: `ai/redaction.service.ts` (`createRedactor`, `placeholderInstruction`) swaps sensitive data for placeholders and maps them back afterwards. New analysis code that sends contract text to the LLM should follow the same pattern. Sensitive fields are encrypted at rest with `utils/fieldEncryption.ts` (`DATA_ENCRYPTION_KEY`).

### Startup seeding
`server.ts` seeds plans, roles, clause taxonomy and contract profiles, and initializes indexes on every boot. Seed data lives in `*.data.ts` files next to their services.

### Billing
Subscriptions and plans are in `services/billing/`; payments use payOS. The webhook (`/api/v1/payments/payos/webhook`) is mounted in `app.ts` **before** the rate limiter and JWT auth, and is authenticated by signature. Prices are computed on the server. See `backend/docs/payos.md`.
